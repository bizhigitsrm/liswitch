# Журнал разработки расширения liswitch (liswitch@local)

Проект: расширение для GNOME Shell 51 (GJS 1.90, только Wayland), улучшающее переключение раскладок клавиатуры.
Файл `docs/PROGRESS.md` является единственной долгосрочной памятью проекта между этапами разработки.

---

## Этап 1. Исследование и справка по API

- **Дата выполнения**: 2026-11-14
- **Статус**: Выполнен

### Что сделано
1. Исследован рантайм GNOME Shell 51.1, Mutter 51.1 и GJS 1.90.1 (Fedora 45 Workstation).
2. Выгружены и детально изучены 200 исходных файлов JS подсистемы GNOME Shell 51 из встроенного ресурса `libshell-51.so`.
3. Разобрана архитектура управления раскладками в `resource:///org/gnome/shell/ui/status/keyboard.js`:
   - Механизм `getInputSourceManager()`, устройство `InputSourceManager` и `InputSource`.
   - Сигналы `current-source-changed`, `sources-changed`, `keymap-changed`.
   - Различие между интерактивной сменой раскладки (`activate(true)` с обновлением MRU) и тихой сменой (`activate(false)` для восстановления состояния окон).
4. Проанализированы системные схемы GSettings:
   - `org.gnome.desktop.input-sources`: ключи `sources`, `current` (подтверждено, что устарел и игнорируется), `mru-sources`, `xkb-options`, `per-window`.
   - `org.gnome.desktop.wm.keybindings`: ключи `switch-input-source` и `switch-input-source-backward`.
5. Изучены механизмы регистрации горячих клавиш: `Main.wm.addKeybinding`, `Main.wm.removeKeybinding`, флаги `Meta.KeyBindingFlags` и режимы `Shell.ActionMode`.
6. Изучено отслеживание фокуса и окон в Wayland: сигнал `notify::focus-window` на `global.display`, свойства и методы `Meta.Window` (`get_id()`, `get_wm_class()`, `get_sandboxed_app_id()`), сигнал очистки окна `unmanaged`.
7. Изучено создание индикатора панели на базе `PanelMenu.Button`, `Main.panel.addToStatusArea`, виджетов `St.Label` и структуры `PopupMenu`.
8. Изучено тестовое окружение GNOME 51: запуск сессии без `--display-server` (вложенный режим по умолчанию), опция `--devkit`, запуск тестов расширения через `gnome-shell-test-tool --extension`, команды утилиты `gnome-extensions`.
9. Сформирован детальный справочник в файле `docs/api-notes.md`.

### Принятые решения и обоснования
1. **Строго синхронный `disable()`**: подтверждено по исходникам `ui/extensionSystem.js`, что возврат `Promise` в GNOME 51 вызывает исключение `disable() must not be async`. Все операции отключения должны выполняться синхронно.
2. **Уникальная роль индикатора в панели**: в `Main.panel.addToStatusArea` запрещено повторно использовать роль `'keyboard'` (вызывает конфликт расширений). Расширение будет регистрировать роль `'liswitch'` и, при необходимости замены, скрывать системный индикатор через `Main.panel.statusArea['keyboard']?.hide()`.
3. **Игнорирование ключа GSettings `current`**: переключение раскладок будет производиться строго через `InputSource.activate()` или `InputSourceManager.activateInputSource()`, так как запись в `current` задепрекейчена и не обрабатывается Shell.
4. **Обязательное подключение к сигналу `unmanaged`**: для предотвращения утечек памяти при отслеживании окон в Wayland все внутренние кэши окон должны очищаться по сигналу `unmanaged`.
5. **Учёт доступности движения (`St.ReducedMotion`)**: любые анимации индикаторов и переходов обязаны проверять `St.Settings.get().reduced_motion !== St.ReducedMotion.REDUCE`.

### Оставшиеся VERIFY и риски
1. `// VERIFY:` Влияние глобального фильтра событий Clutter Stage (`global.stage.connect('captured-event', ...)`) на задержку ввода — если на последующих этапах понадобится перехват клавиш до того, как они попадут в Wayland-клиент.
2. Риск конфликта с пользовательскими комбинациями в `org.gnome.desktop.input-sources xkb-options` (например, Alt+Shift, перехватываемый на уровне libxkbcommon через `modifiers-accelerator-activated`).

### Принятые решения и обоснования
1. **Исключение `unlock-dialog` из `session-modes`**: в `metadata.json` указывается только `["user"]`. Расширение автоматически выгружается на экране блокировки, гарантируя стабильность PAM-диалога ввода пароля и соблюдая гайдлайны безопасности EGO.
2. **Модульная структура в `src/`**: разделение ответственности между специализированными сервисами исключает разрастание монолитного кода в `extension.js` и упрощает изолированное тестирование.
3. **Синхронный LIFO-демонтаж**: все ресурсы уничтожаются строго в обратном порядке создания (`Indicator` → `Hotkeys` → `OSD` → `Memory` → `InputSources` → `Settings`). Возврат промисов исключён.
4. **Тихая активация (`interactive = false`) для памяти окон**: при смене фокуса активная раскладка восстанавливается через `activate(false)`, что обновляет состояние Mutter/XKB без перетасовки системного списка `mru-sources`.
5. **Безопасное замещение системных шорткатов**: перехват системного `<Super>space` выполняется только при явном согласии пользователя с обязательным сохранением исходных значений в `backup-system-switch-keys` и 100% восстановлением в `disable()`.

### Оставшиеся VERIFY и риски

## Этап 4. Сервис работы с раскладками (`src/inputSourceService.js`)

- **Дата выполнения**: 2026-11-14
- **Статус**: Выполнен

### Что сделано
1. Создан единый хелпер логирования `src/log.js` с функциями `initLogger()`, `resetLogger()`, `debug()`, `info()`, `warn()`, `error()`. Логирование `debug` выводится в системный журнал только при активном ключе GSettings `debug` (или явном переопределении для тестов через `setDebugOverride`).
2. Разработан сервис работы с раскладками `src/inputSourceService.js` с классом `InputSourceService`:
   - Наследование от `GObject.Object` со строгой типизацией сигналов: `sources-changed` и `current-changed(index: GObject.TYPE_INT)`.
   - Легковесный `constructor(settings)` без тяжёлых операций.
   - Метод `enable({manager = null})`: подключение к сигналам Shell `sources-changed` и `current-source-changed`, получение менеджера через `getInputSourceManager()` (или мока), синхронизация списка раскладок и текущего индекса.
   - Метод `destroy()`: строго синхронное отключение всех слушателей сигналов, очистка кэшей, сброс ссылок, идемпотентность при повторных вызовах.
   - Метод `getSources()`: возвращает нормализованный массив объектов `{index, id, shortName, displayName}`.
   - Метод `getCurrentIndex()`: возвращает целочисленный индекс активной раскладки (0..N) или `-1`, если сервис недоступен.
   - Метод `activate(index, interactive = true)`: переключение раскладки с валидацией индекса; при невалидном индексе безопасно игнорирует команду и пишет предупреждение в журнал, если включён `debug`.
   - Методы `next()` и `previous()`: циклическое переключение раскладок по кругу с учётом позиции в массиве доступных источников.
   - Геттеры `isAvailable` (boolean) и `state` (`'available'` | `'unavailable'`).
   - Безопасная обработка граничных случаев: при недоступности менеджера или пустом списке источников сервис переходит в `unavailable`, возвращает пустой список раскладок и `-1`, а расширение не падает.
3. Разработан запасной путь `FallbackBackend` на базе схемы `org.gnome.desktop.input-sources`:
   - Активируется исключительно при недоступности `InputSourceManager` (например, в standalone CLI-окружении или при сбое инициализации клавиатурной подсистемы Shell).
   - Читает `sources` и `current` из GSettings, отслеживает сигналы `changed::sources` и `changed::current`.
   - В комментариях к классу задокументировано, почему в GNOME Shell 50/51 на Wayland системный ключ `current` устарел и игнорируется Mutter, и почему запись в него не переключает активную раскладку в сессии.
4. В комментариях к классу подробно описаны используемые внутренние поля Shell (`InputSourceManager`, `InputSource`, словарь `inputSources`, порядок `_mruSources`, нормализация `shortName`).
5. Обновлена точка входа расширения `extension.js`:
   - Интегрированы `InputSourceService` и `log.js`.
   - В `enable()` создаётся и включается сервис раскладок.
   - В `disable()` сервис синхронно уничтожается (`destroy()`) и обнуляется ссылка.
   - Добавлен публичный геттер `inputSourceService` для удобного доступа из Looking Glass (`Alt+F2` -> `lg`) и тестов.
6. В `Makefile` и `scripts/dev-run.sh` добавлен флаг `--extra-source=src` для команды `gnome-extensions pack`, гарантирующий включение файлов `src/inputSourceService.js` и `src/log.js` в архив расширения.
7. Создан модульный автоматический тест `tests/test-input-source-service.js` для чистого GJS (`gjs -m tests/test-input-source-service.js`), проверяющий:
   - Инициализацию и контракт `getSources()` ({index, id, shortName, displayName}).
   - `activate(index)` с валидными индексами и генерацию `current-changed`.
   - Циклическое переключение `next()` и `previous()`.
   - Безопасную обработку невалидных индексов и логирование `debug`.
   - Динамическое удаление и добавление раскладок по сигналу `sources-changed`, переход в `unavailable` при пустом списке.
   - 20 циклов `enable()`/`destroy()` без утечек сигнатур и дублирования обработчиков.

### Принятые решения и обоснования

### Принятые решения и обоснования
1. **Строгое хранение истории только в оперативной памяти (RAM)**:
   В соответствии с правилами приватности extensions.gnome.org и требованиями ТЗ, история активных окон и сопоставленных раскладок никогда не сохраняется в GSettings или на диск.
2. **Тихая активация раскладки (`interactive = false`)**:
   Вызов `activate(index, false)` обновляет активную раскладку XKB в Mutter, не изменяя порядок в системном ключе `mru-sources`. Это предотвращает разрушение порядка истории переключения по Super+Space.
3. **Строгая дедупликация и проверка `targetSource.index !== currentIndex`**:
   Гарантирует, что при получении фокуса окном, у которого активная раскладка уже совпадает с сохранённой (или при повторных событиях `notify::focus-window` на одном окне), метод `activate()` не вызывается вовсе (0 вызовов). При необходимости смены вызывается ровно один раз.
4. **LRU-кэш на базе JavaScript `Map` (максимум 500 записей)**:
   Поскольку JS `Map` сохраняет порядок вставки ключей, перемещение accessed-ключа в конец и удаление первого ключа (`map.keys().next().value`) реализует идеальный O(1) LRU-кэш без дополнительных библиотек.
5. **Безопасная обработка системного `per-window`**:
   Liswitch автоматически определяет активность системного флага `org.gnome.desktop.input-sources per-window` и приостанавливает собственное переключение, извещая пользователя в окне настроек и логах. Это исключает гонки двух независимых механизмов.
