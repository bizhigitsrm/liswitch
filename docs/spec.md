# Спецификация функциональности расширения liswitch

- **Идентификатор расширения (UUID)**: `liswitch@local`
- **Целевая платформа**: GNOME Shell 51 (GJS 1.90, Mutter 51, только сессия Wayland)
- **Версия документа**: 1.0 (Этап 2)
- **Статус**: Утверждена для реализации

---

## 1. Введение и цели проекта

Расширение «liswitch» предназначено для устранения давних проблем и ограничений переключения раскладок клавиатуры в GNOME Shell на Wayland:
1. Запоминание активной раскладки для каждого приложения или отдельного окна с мгновенным бесшовным восстановлением при смене фокуса.
2. Предоставление независимых, надёжно настраиваемых горячих клавиш (циклическое переключение вперёд/назад, прямое переключение на раскладки 1–4).
3. Информативный индикатор в верхней панели с кастомизацией формата и удобным меню выбора.
4. Легковесный всплывающий OSD-индикатор переключения с полной поддержкой стандартов доступности (`St.ReducedMotion`).
5. Нативное окно настроек на базе Libadwaita, следующее актуальным HIG GNOME.

Документ описывает поведение системы, все граничные случаи и методики ручной проверки для каждой функции MVP (F1–F5), а также архитектурный задел для перспективной функции F6 (Этап 9).

---

## 2. Общие принципы и ограничения среды

1. **Только Wayland**: Сессия X11 в GNOME Shell 50/51 полностью удалена. Все механизмы опираются исключительно на API Mutter, Clutter и Wayland-композитора.
2. **Строго синхронный жизненный цикл**: В соответствии с правилами GNOME Shell 51 метод `disable()` обязан быть строго синхронным. Запрещены асинхронные операции и возвраты `Promise`.
3. **Безопасность и конфиденциальность**: Расширение не читает, не перехватывает и не логирует текст, вводимый пользователем в окнах приложений.
4. **Уважение системных настроек**: Глобальные параметры GNOME не модифицируются без явного согласия пользователя. Любые временно изменённые настройки гарантированно восстанавливаются в `disable()`.
5. **Чистый GJS/ESM**: Отсутствие внешних runtime-зависимостей, модулей npm и фоновых бинарных процессов.

---

## 3. Функциональные требования (MVP)

### F1. Индикатор в верхней панели

#### Поведение
1. **Регистрация в панели**:
   - Расширение регистрирует кнопку панели (`PanelMenu.Button`) с уникальной ролью `'liswitch'` через `Main.panel.addToStatusArea('liswitch', indicator, 0, 'right')`.
   - Использование системной роли `'keyboard'` запрещено во избежание конфликтов расширений (`Extension point conflict`).
2. **Отображение текущей раскладки**:
   - Индикатор содержит текстовую метку `St.Label`, отображающую короткий код активной раскладки.
   - Источником данных является `InputSourceManager.currentSource`.
   - При смене раскладки (сигнал `current-source-changed`) текст обновляется мгновенно без мерцания.
   - Формат отображения определяется настройкой `indicator-format`:
     - `'uppercase'` (по умолчанию): `EN`, `RU`, `KK`.
     - `'lowercase'`: `en`, `ru`, `kk`.
     - `'full'`: краткое имя с вариантом (например, `EN-intl`, `RU-typewriter`).
3. **Меню индикатора**:
   - Нажатие левой кнопкой мыши открывает выпадающее меню (`PopupMenu.PopupMenu`).
   - В меню перечисляются все сконфигурированные раскладки из `InputSourceManager.inputSources`.
   - Каждый пункт отображает полное человекочитаемое имя раскладки (`source.displayName`).
   - Активная раскладка помечается точкой-орнаментом (`PopupMenu.Ornament.DOT`).
   - Клик по пункту меню активирует выбранную раскладку в интерактивном режиме (`source.activate(true)`), закрывает меню и обновляет индикатор.
   - Ниже списка раскладок через разделитель (`PopupMenu.PopupSeparatorMenuItem`) размещается пункт «Настройки Liswitch...», открывающий окно настроек расширения.
4. **Управление системным индикатором**:
   - Если включена опция `hide-system-indicator` (по умолчанию `true`), стандартный системный индикатор скрывается вызовом `Main.panel.statusArea['keyboard']?.hide()`.
   - При отключении расширения (`disable()`) системный индикатор восстанавливается: `Main.panel.statusArea['keyboard']?.show()`.

#### Граничные случаи
- **0 настроенных раскладок**: Если в системе нет ни одной раскладки, индикатор показывает заглушку `--`, меню содержит один неактивный пункт `_('No layouts configured')`. Ошибок не генерируется.
- **1 настроенная раскладка**: Индикатор отображает её код. Клик открывает меню с одним пунктом.
- **Динамическое изменение списка раскладок**: При добавлении или удалении раскладок пользователем в системных настройках GNOME генерируется сигнал `sources-changed`. Индикатор полностью перестраивает пункты меню, сверяет актуальность текущей раскладки и обновляет метку.
- **Нестандартные или пустые `shortName`**: Если у `InputSource` отсутствует или пуст `shortName`, берётся срез первых двух символов из `id` (например, `'us'` → `'US'`).
- **Скрытие индикатора по настройке**: Если ключ `indicator-enabled` переключается в `false`, кнопка индикатора скрывается из панели (`indicator.hide()`), но системный индикатор возвращается на место.

#### Как проверить вручную
1. Включить расширение через `gnome-extensions enable liswitch@local`.
2. Убедиться, что в правом блоке верхней панели появился индикатор (например, `EN`), а стандартный индикатор клавиатуры скрыт.
3. Кликнуть по индикатору: раскрывается меню со списком всех установленных раскладок, у текущей стоит отметка.
4. Кликнуть по другой раскладке (например, `Русская`): меню закрывается, индикатор меняется на `RU`, системная раскладка переключена.
5. Открыть параметры GNOME (Регион и язык), добавить третью раскладку (например, `Казахская`). Открыть меню liswitch — пункт `KK` появился автоматически.
6. Выполнить `gnome-extensions disable liswitch@local`: индикатор liswitch исчезает, стандартный индикатор GNOME мгновенно возвращается.

### F2. Собственные горячие клавиши и управление конфликтами

#### Поведение
1. **Поддерживаемые действия**:
   - `switch-next`: переход к следующей раскладке в списке (циклически).
   - `switch-prev`: переход к предыдущей раскладке в списке (циклически).
   - `switch-to-1`: прямой выбор первой раскладки из списка источников (индекс 0).
   - `switch-to-2`: прямой выбор второй раскладки (индекс 1).
   - `switch-to-3`: прямой выбор третьей раскладки (индекс 2).
   - `switch-to-4`: прямой выбор четвёртой раскладки (индекс 3).
2. **Регистрация в оконном менеджере**:
   - Привязки регистрируются через `Main.wm.addKeybinding()` с использованием собственных ключей GSettings схемы `org.gnome.shell.extensions.liswitch`.
   - Флаги: `Meta.KeyBindingFlags.IGNORE_AUTOREPEAT` (предотвращает множественное неконтролируемое срабатывание при зажатой клавише).
   - Режимы активности: `Shell.ActionMode.NORMAL | Shell.ActionMode.OVERVIEW | Shell.ActionMode.POPUP`. Это обеспечивает работу шорткатов в нормальном режиме, в режиме обзора (Overview) и при открытых выпадающих меню панели.
3. **Интерактивность активации**:
   - Переключение по горячим клавишам пользователя выполняется в интерактивном режиме `source.activate(true)`. Это обеспечивает синхронизацию системного порядка MRU (`mru-sources`).

#### Конфликт со стандартными `switch-input-source`
1. **Механизм обнаружения конфликтов**:
   - При старте и при изменении настроек liswitch проверяет:
     - Системную схему `org.gnome.desktop.wm.keybindings`: ключи `switch-input-source` и `switch-input-source-backward`.
     - Системную схему `org.gnome.desktop.input-sources`: ключ `xkb-options` (на наличие модификаторов переключения вроде `grp:alt_shift_toggle`, `grp:caps_toggle`, `grp:ctrl_shift_toggle`).
   - Если назначенное пользователем сочетание в liswitch совпадает со значением в системных схемах, фиксируется конфликт.
2. **Стратегия разрешения конфликта**:
   - **По умолчанию (`manage-system-shortcuts = false`)**: liswitch не трогает системные ключи. В окне настроек выводится предупреждающий информационный баннер:
     > *«Сочетание \<Super\>space назначено системным переключателем GNOME Shell. Чтобы liswitch управлял этим сочетанием, включите опцию 'Замещать системные горячие клавиши' или измените системную привязку.»*
   - **При включении `manage-system-shortcuts = true`**:
     1. Расширение считывает текущие значения `switch-input-source` и `switch-input-source-backward` из `org.gnome.desktop.wm.keybindings`.
     2. Сохраняет их в резервные ключи собственной схемы: `backup-system-switch-keys` и `backup-system-switch-backward-keys`.
     3. Очищает системные ключи в `org.gnome.desktop.wm.keybindings` (устанавливает пустые массивы `[]`), чтобы Mutter не обрабатывал их своим стандартным обработчиком с вызовом `InputSourcePopup`.
     4. Регистрирует шорткаты liswitch на эти комбинации.
   - **Откат и восстановление при `disable()`**:
     - В методе `disable()` расширение ОБЯЗАНО восстановить значения системных ключей `switch-input-source` и `switch-input-source-backward` из резервной копии.
   - **Особый случай: аппаратные модификаторы (`xkb-options`)**:
     - Если переключение назначено на голые модификаторы (например, Alt+Shift или CapsLock), Mutter обрабатывает их на уровне XKB через сигнал `modifiers-accelerator-activated`.
     - `Main.wm.addKeybinding` технически не может перехватить голые модификаторы без комбинации с обычной клавишей.
     - Окно настроек liswitch явно информирует пользователя о невозможности переопределения голых модификаторов через `addKeybinding` и предлагает настроить сочетания вида `<Super>space`, `<Alt>space`, `<Shift><Super>space` либо комбинации с цифрами.

#### Граничные случаи
- **Попытка прямого переключения на отсутствующую раскладку**: Если нажата клавиша `switch-to-4`, а в системе настроено только 2 раскладки, обработчик игнорирует вызов (no-op), звуковых сигналов ошибки или исключений не выбрасывается.
- **Очистка сочетания (пустой шорткат)**: Если в настройках сочетание очищено (`[]`), вызывается `Main.wm.removeKeybinding()`, обработчик отключается.
- **Конкурирующие расширения**: Если другое расширение уже перехватило шорткат, `Main.wm.addKeybinding` возвратит ошибку; liswitch корректно перехватывает исключение и уведомляет пользователя в логах.

#### Как проверить вручную
1. В настройках liswitch задать шорткат для следующей раскладки: `['<Super>grave']` (клавиша тильды).
2. Задать прямой выбор: `switch-to-1` = `['<Alt>1']`, `switch-to-2` = `['<Alt>2']`.
3. Нажать `<Alt>2` — раскладка переключилась на вторую.
4. Нажать `<Alt>1` — раскладка переключилась на первую.
5. Нажать `<Super>grave` — раскладки циклически переключаются по кругу.
6. Включить опцию «Замещать системные горячие клавиши», назначить `<Super>space` в liswitch. Убедиться, что стандартный всплывающий переключатель GNOME не появляется, а переключение выполняет liswitch.
7. Отключить расширение — проверить, что системное поведение `<Super>space` полностью восстановилось.

### F3. Запоминание раскладки по приложению и по окну

#### Поведение
1. **Отслеживание смены фокуса**:
   - Сервис памяти подписывается на сигнал `notify::focus-window` объекта `global.display`.
   - При смене активного окна считывается `global.display.focus_window`.
2. **Формирование ключа идентификации**:
   - **Режим «По приложению» (`memory-mode = 'app'`)**:
     - Ключ вычисляется по приоритету:
       `window.get_sandboxed_app_id() || window.get_gtk_application_id() || window.get_wm_class() || 'fallback-app'`
     - Это гарантирует корректную изоляцию для Flatpak/Snap и классических приложений.
   - **Режим «По окну» (`memory-mode = 'window'`)**:
     - Ключ вычисляется как строковое представление `window.get_id()` (уникальный 64-битный ID окна Mutter).
   - **Режим «Отключено» (`memory-mode = 'none'`)**:
     - Запоминание и автоматическое восстановление не производятся.
3. **Список исключений (`excluded-apps`)**:
   - Перед обработкой проверяется наличие `app_id` / `wm_class` в массиве `excluded-apps`.
   - Если приложение в списке исключений, память для него игнорируется: текущая раскладка остаётся неизменной при переходе в это окно.
4. **Восстановление раскладки при получении фокуса**:
   - Если для полученного ключа в кэше сохранена раскладка (`savedSourceId`):
     - В текущих `InputSourceManager.inputSources` находится соответствующий объект `InputSource`.
     - Если найденный источник отличается от активного, вызывается **тихая активация**:
       `source.activate(false)` (флаг `interactive = false`).
     - Использование `interactive = false` критически важно: оно меняет XKB-маппинг, но НЕ перемещает раскладку в начало системного списка `mru-sources`.
   - Если в кэше нет сохранённой раскладки для этого ключа:
     - Если `default-layout-mode = 'first'`, тихо активируется первая раскладка из списка (`sources[0]`).
     - Если `default-layout-mode = 'keep'`, текущая системная раскладка сохраняется как начальная для данного ключа.
5. **Сохранение раскладки при ручном переключении**:
   - Сервис слушает сигнал `current-source-changed` в `InputSourceManager`.
   - Если активно валидное окно (не входящее в `excluded-apps`), идентификатор новой раскладки сохраняется в кэш для текущего ключа (окна или приложения).

#### Граничные случаи
- **Фокус переходит в системные элементы (`focus_window === null`)**:
  - При открытии Overview, клике на свободное место панели или рабочий стол `focus_window` становится `null`. Сервис памяти игнорирует событие и не сбрасывает состояние.
- **Закрытие окна и предотвращение утечек памяти**:
  - При отслеживании окон сервис подключается к сигналу `'unmanaged'` каждого нового окна через `window.connectObject('unmanaged', () => ..., this)`.
  - При закрытии окна его ID немедленно удаляется из кэша оконного режима, а обработчики отключаются.
- **Удаление раскладки из системы во время сессии**:
  - Если для приложения была сохранена раскладка `KK`, а пользователь удалил её в настройках ОС, при последующем фокусе сохранённый ID не будет найден среди доступных `inputSources`. Сервис выполняет безопасный fallback: активирует `sources[0]` и обновляет запись в кэше.
- **Системная опция `org.gnome.desktop.input-sources per-window`**:
  - Если системная опция `per-window` включена одновременно с liswitch, возникает конфликт двойного переключения.
  - liswitch при включении F3 информирует пользователя о необходимости отключить системный `per-window`, либо автоматически отключает системный флаг на время своей работы, восстанавливая его при `disable()`.

#### Как проверить вручную
1. Выбрать режим памяти «По приложению» (`memory-mode = 'app'`).
2. Запустить Текстовый редактор (`org.gnome.TextEditor`) и Терминал (`org.gnome.Console`).
3. Сфокусироваться на Редакторе, переключить раскладку на `RU`. Напечатать «тест».
4. Сфокусироваться на Терминале, переключить раскладку на `EN`. Напечатать `ls`.
5. Переключиться по Alt+Tab в Редактор: индикатор liswitch мгновенно показывает `RU`, ввод идёт на русском.
6. Переключиться обратно в Терминал: индикатор показывает `EN`, ввод идёт на английском.
7. Переключить режим на «По окну». Открыть два окна Текстового редактора. В одном установить `EN`, в другом `RU`. Проверить независимость раскладок между окнами одной программы.
8. Добавить `org.gnome.Console` в список исключений: проверить, что при переходе в консоль раскладка больше не подменяется принудительно.

### F4. Визуальная обратная связь (OSD Pop-up)

#### Поведение
1. **Условия отображения**:
   - При смене раскладки (по горячей клавише, кликом в меню или системным действием), если включен ключ `show-osd = true`.
2. **Внешний вид и размещение**:
   - Всплывающее окно отображается в центре монитора, на котором находится активное окно (или на основном мониторе `Main.layoutManager.primaryIndex`, если окно отсутствует).
   - Окно содержит крупную метку раскладки (например, `EN`, `RU`, `KK`) и иконку клавиатуры (`input-keyboard-symbolic`).
   - Используется нативный механизм `Main.osdWindowManager.showOne(monitorIndex, icon, label)` либо собственный легковесный контейнер `St.Widget` в `Main.uiGroup`, оформленный через `stylesheet.css`.
3. **Длительность и скрытие**:
   - Окно отображается в течение времени, заданного в `osd-duration-ms` (по умолчанию 1000 мс).
   - По истечении таймера окно плавно исчезает (fade-out) за 200 мс.
4. **Учёт доступности движения (`St.ReducedMotion`)**:
   - Перед запуском анимации проверяется состояние:
     `St.Settings.get().reduced_motion === St.ReducedMotion.REDUCE`
   - Если `REDUCE`, анимация прозрачности полностью отключается (длительность перехода 0 мс), окно скрывается мгновенно по завершении таймера.

#### Граничные случаи
- **Серия быстрых переключений**: Если пользователь быстро нажимает клавишу переключения несколько раз подряд, текущий таймер скрытия сбрасывается (`GLib.source_remove`), текст мгновенно заменяется на актуальный, и запускается свежий интервал ожидания. Никаких наложений или застреваний плашек на экране.
- **Полноэкранные приложения (игры, видео)**: OSD отображается поверх контента без перехвата фокуса клавиатуры или мыши (`reactive = false`, `can_focus = false`).
- **Отключение расширения во время показа OSD**: В методе `disable()` любой активный таймер OSD немедленно аннулируется, а виджет удаляется со сцены.

#### Как проверить вручную
1. Включить `show-osd = true`. Нажать горячую клавишу переключения — убедиться, что по центру экрана на 1 секунду появляется стильное уведомление с именем раскладки.
2. Быстро нажать шорткат 5 раз подряд — убедиться, что OSD непрерывно обновляет буквенный код и плавно исчезает только после паузы в нажатиях.
3. Включить системную опцию уменьшения движения:
   `gsettings set org.gnome.desktop.interface enable-animations false`
   Убедиться, что OSD исчезает резко, без анимации затухания.
4. Отключить расширение `gnome-extensions disable liswitch@local` в момент показа OSD — окно должно исчезнуть мгновенно без зависания на экране.

### F5. Окно настроек на Libadwaita (`prefs.js`)

#### Поведение
1. **Точка входа**:
   - Класс `LiswitchPreferences` наследуется от `ExtensionPreferences` из `resource:///org/gnome/Shell/Extensions/js/extensions/prefs.js`.
   - Метод `fillPreferencesWindow(window)` наполняет окно `Adw.PreferencesWindow`.
2. **Структура страниц и групп**:
   - **Вкладка «Основные» (General)**:
     - Группа «Индикатор в панели»:
       - `indicator-enabled` (`Adw.SwitchRow`): Включение/отключение кнопки в панели.
       - `hide-system-indicator` (`Adw.SwitchRow`): Скрытие системного индикатора GNOME.
       - `indicator-format` (`Adw.ComboRow`): Формат подписи (`Верхний регистр (EN)`, `Нижний регистр (en)`, `Полный`).
     - Группа «Уведомления (OSD)»:
       - `show-osd` (`Adw.SwitchRow`): Показывать всплывающее окно при переключении.
       - `osd-duration-ms` (`Adw.SpinRow`): Длительность отображения (от 300 до 3000 мс, шаг 100 мс).
   - **Вкладка «Память раскладки» (Memory)**:
     - Группа «Режим сохранения»:
       - `memory-mode` (`Adw.ComboRow`): «По приложениям», «По отдельным окнам», «Отключено».
       - `default-layout-mode` (`Adw.ComboRow`): Действие для новых окон («Сохранять текущую», «Сбрасывать на первую»).
     - Группа «Исключения»:
       - `excluded-apps`: Список идентификаторов приложений, исключённых из запоминания, с кнопками добавления и удаления (`Adw.EntryRow` / список `Gtk.ListBox`).
   - **Вкладка «Горячие клавиши» (Shortcuts)**:
     - Группа «Управление конфликтами»:
       - `manage-system-shortcuts` (`Adw.SwitchRow`): Замещать системные шорткаты переключения GNOME.
       - Информационный баннер (`Adw.Banner` или статус-метка) о статусе системного шортката `<Super>space`.
     - Группа «Переключение раскладок»:
       - Строка «Следующая раскладка» (`switch-next-shortcut`) с диалогом захвата сочетания клавиш.
       - Строка «Предыдущая раскладка» (`switch-prev-shortcut`).
     - Группа «Прямой выбор»:
       - Строки «Раскладка 1» – «Раскладка 4» (`switch-to-1-shortcut` ... `switch-to-4-shortcut`).
3. **Двусторонняя привязка**:
   - Все переключатели и комбо-боксы связываются со схемой GSettings через `settings.bind()` с соответствующими флагами `Gio.SettingsBindFlags.DEFAULT`. Изменения применяются мгновенно без необходимости перезапуска.

#### Граничные случаи
- **Открытие настроек при выключенном расширении**: Окно настроек запускается в отдельном процессе (`gnome-extensions-app`). Оно не зависит от объекта `Main` и оперирует исключительно объектом `Gio.Settings`.
- **Ввод недопустимого сочетания клавиш**: Захватчик клавиш валидирует код акселератора через `Gtk.accelerator_parse()`. Невалидные комбинации отбрасываются, сохраняя предыдущее значение.

#### Как проверить вручную
1. Открыть окно настроек командой `gnome-extensions prefs liswitch@local`.
2. Изменить формат подписи индикатора на `Нижний регистр`. Проверить, что индикатор на панели сменился на `en`/`ru`.
3. Отключить показ OSD. Проверить, что всплывающее окно перестало появляться при переключении.
4. Добавить новое сочетание клавиш для `switch-next`. Проверить, что оно записалось в GSettings (`gsettings --schemadir schemas/ get org.gnome.shell.extensions.liswitch switch-next-shortcut`).

### F6. (Перспектива Этапа 9) Конвертация набранного слова

*Данная функция является опциональной и запланирована к реализации на Этапе 9. На этапе архитектуры фиксируются принципиальные ограничения и техническая концепция.*

1. **Концепция**:
   - Нажатие выделенной горячей клавиши (например, `Pause/Break` или `Shift+Pause`) преобразует последнее введённое ошибочное слово (например, `ghbdtn` → `привет`) и переключает раскладку на парную.
2. **Ограничения Wayland**:
   - В сессии Wayland расширение GNOME Shell не имеет права глобально перехватывать чужой ввод в фоновом режиме (keylogger) и не имеет доступа к внутреннему тексту чужих текстовых полей.
3. **Планируемый механизм реализации**:
   - Использование механизма буфера обмена и синтетических событий клавиатуры:
     1. Выделение предыдущего слова: генерация комбинации `Shift+Ctrl+Left`.
     2. Вырезание в системный буфер обмена: генерация `Ctrl+X`.
     3. Перехват содержимого буфера через `St.Clipboard`.
     4. Транслитерация/перекодирование по таблице соответствия символов XKB (`Q` ↔ `Й` и т.д.).
     5. Запись сконвертированного текста обратно в буфер обмена.
     6. Вставка обратно: генерация `Ctrl+V`.
     7. Переключение активной раскладки на целевую.
4. **Критерии безопасности**:
   - Никаких фоновых логов, буфер очищается или восстанавливается после завершения операции.
